Fine-tuning a large language model used to require a cluster of GPUs and a PhD in distributed systems. Today, thanks to [parameter-efficient fine-tuning](/articles/lora-fine-tuning-llms) (PEFT) methods like LoRA and QLoRA, you can fine-tune a 7B model on a single consumer GPU. This guide walks through the practical steps.

## Why Fine-Tune?

Fine-tuning makes sense when prompting alone isn't enough. The key scenarios:

- **Domain adaptation**: Your domain has specific terminology, formats, or reasoning patterns that a general model doesn't handle well.
- **Style/voice consistency**: You need consistent output formatting or tone across many generations.
- **Cost reduction**: A fine-tuned smaller model can outperform a prompted larger model, reducing [inference](/articles/tensorrt-inference-acceleration) costs.

<Callout type="warning">
Fine-tuning is not a silver bullet. If your model gets facts wrong, fine-tuning won't fix the underlying knowledge gap. RAG (retrieval-augmented generation) is often the better first step.
</Callout>

## Dataset Preparation

The quality of your dataset matters more than its size. 500 high-quality examples will outperform 50,000 noisy ones.

**Instruction format**: Most fine-tuning uses an instruction-response format:

```json
{"instruction": "Explain how RBAC works in Kubernetes", "output": "RBAC in Kubernetes uses four objects: Role, ClusterRole, RoleBinding, and ClusterRoleBinding..."}
```

**Quality over quantity**: Manually review every example. Remove duplicates, fix formatting inconsistencies, and ensure responses are accurate. A single bad example can degrade model quality.

**Train/eval split**: Hold out 10-20% for evaluation. Without this, you can't detect overfitting.

## LoRA and QLoRA

**LoRA (Low-Rank Adaptation)**: Instead of updating all model weights, LoRA adds small trainable rank-decomposition matrices alongside each weight matrix. Only these small matrices are updated during training, reducing trainable parameters by 99%+.

```python
from peft import LoraConfig, get_peft_model

config = LoraConfig(
    r=16,                    # rank — higher = more capacity
    lora_alpha=32,           # scaling factor
    target_modules=["q_proj", "v_proj"],  # which layers to adapt
    lora_dropout=0.05,
    task_type="CAUSAL_LM",
)
model = get_peft_model(base_model, config)
```

**QLoRA**: Combines LoRA with 4-bit quantization of the base model. The base model weights are frozen at 4-bit precision, and only the LoRA adapters are trained at full precision. This lets you fine-tune a 65B model on a single 48GB GPU.

**Hyperparameter selection**:
- `r` (rank): 8-64. Start with 16. Higher values add capacity but risk overfitting.
- `lora_alpha`: Typically 2x the rank.

Controls how much the LoRA updates affect the model.
- `target_modules`: `["q_proj", "v_proj"]` is a good default. Adding `k_proj`, `o_proj` can improve quality at the cost of more parameters.

## Training and Evaluation

Monitor these metrics during training:

- **Loss curve**: Should decrease smoothly. A sudden spike often indicates a bad batch or learning rate too high.
- **Eval loss**: If eval loss diverges from training loss, you're overfitting. Reduce the number of epochs or increase dropout.
- **Gradient norm**: If it explodes, your learning rate is too high or you need gradient clipping.

**Avoiding catastrophic forgetting**: Fine-tuning can make the model forget its pre-trained capabilities. Mitigations:
- Use a low learning rate (1e-4 to 1e-5 for LoRA)
- Limit training epochs (1-3 is often enough)
- Mix in some general data with your domain-specific data

## Deployment Considerations

After fine-tuning, you need to deploy:

- **Merging adapters**: For LoRA, merge the adapters back into the base model for inference: `model.merge_and_unload()`. This eliminates the overhead of applying adapters at inference time.
- **Serving**: Use vLLM, TGI, or similar for production serving. They support LoRA adapters natively.
- **Versioning**: Track the base model, adapter, and training data version. A model card documenting all three is essential for reproducibility.

<Note>
Fine-tuning is iterative. Start with a small dataset, a low rank, and 1-2 epochs. Evaluate, then scale up the things that work. Don't start with 10,000 examples and 10 epochs — you'll waste time and GPU budget.
</Note>
