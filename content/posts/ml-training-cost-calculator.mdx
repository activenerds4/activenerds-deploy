Nothing stings like realizing your training run cost $2,400 when you budgeted $800 — and you're only halfway through epoch 30. Estimating GPU training costs before you hit "run" is one of those unglamorous MLOps skills that saves real money, especially when you're iterating on hyperparameters or scaling up model size.

This guide gives you the formula, the pricing reference, and a template you can drop into a spreadsheet today.

## The Cost Equation

Training cost breaks down to a deceptively simple formula:

```
Total Cost = (GPU_Hours × Hourly_Rate) + Storage_Cost + Data_Transfer_Cost
```

Where `GPU_Hours = (Total_Steps × Step_Time_Seconds) / 3600`

The tricky part is estimating `Step_Time_Seconds` accurately before you run. The best approach: run 100 steps on your target hardware, measure the average step time, and extrapolate. Don't trust theoretical FLOPS calculations — they rarely match reality due to data loading overhead, gradient synchronization, and framework overhead.

<Note>
Always include a 20-30% buffer in your estimate. Training runs frequently take longer than projected due to checkpointing, evaluation, and unexpected bottlenecks.
</Note>

### Spot vs On-Demand

Spot instances can cut costs by 60-70%, but they come with preemption risk. For runs under 4 hours, spot is almost always worth it. For multi-day training runs, calculate the cost of checkpoint recovery: if you expect 2-3 preemptions on a 3-day run, add the checkpoint load time and restart overhead to your total.

### Hidden Costs

Don't forget these often-overlooked expenses:

- **EBS/gp3 storage**: ~$0.08/GB/month for checkpoint storage
- **S3/GCS data transfer**: First 100GB free, then $0.09/GB (AWS)
- **NAT gateway**: $0.045/hour + $0.045/GB processed
- **Load balancer**: If you're serving during training

## Building the Calculator

Here's a Python snippet you can adapt into a quick calculator:

```python
def estimate_training_cost(
    total_steps: int,
    step_time_sec: float,
    gpu_hourly_rate: float,
    num_gpus: int = 1,
    storage_gb: float = 100,
    spot_discount: float = 0.0,
    buffer_pct: float = 0.25,
):
    total_seconds = total_steps * step_time_sec
    gpu_hours = (total_seconds / 3600) * num_gpus
    effective_rate = gpu_hourly_rate * (1 - spot_discount)
    compute_cost = gpu_hours * effective_rate
    storage_cost = (storage_gb * 0.08) / 30  # monthly prorated
    total = (compute_cost + storage_cost) * (1 + buffer_pct)
    return {
        "gpu_hours": gpu_hours,
        "compute_cost": compute_cost,
        "storage_cost": storage_cost,
        "total_estimated": total,
    }

# Example: 50K steps, 2s/step, 8× A100 spot
result = estimate_training_cost(
    total_steps=50000,
    step_time_sec=2.0,
    gpu_hourly_rate=32.77,
    num_gpus=8,
    spot_discount=0.7,
)
print(f"Estimated cost: ${result['total_estimated']:.2f}")
# Output: Estimated cost: $431.55
```

## Cost Optimization Strategies

**Mixed precision training** can cut step time by 30-50%, directly reducing GPU-hours. If you're not using AMP (`torch.cuda.amp`), you're overpaying for compute.

**Gradient accumulation** lets you simulate larger batch sizes on fewer GPUs, which can reduce your instance requirements from 8 GPUs to 2-4 for the same effective batch size.

**Spot instances with checkpointing** are the single biggest cost lever. A well-implemented checkpoint recovery system (save every N steps to S3/GCS) makes spot viable even for long runs.

**Right-sizing instances**: don't rent 8× H100 if your model fits in 4× A100. Profile your memory usage and pick the smallest instance that fits with 20% headroom.
