## This Month's CVEs

### Critical Vulnerabilities

**CVE-2025-1974 — Kubernetes ingress-nginx RCE**
- **Severity**: Critical (CVSS 9.8)
- **Affected**: ingress-nginx < 1.12.1 and < 1.11.5
- **Impact**: Remote code execution via crafted annotations in Ingress resources. Any user who can create or modify Ingress objects can execute code in the controller pod.
- **Patch**: Upgrade to ingress-nginx 1.12.1 or 1.11.5 immediately
- **Workaround**: Restrict Ingress creation permissions via RBAC

```bash
# Check your ingress-nginx version
kubectl get deployment -n ingress-nginx ingress-nginx-controller -o jsonpath='{.spec.template.spec.containers[0].image}'

# Upgrade
helm upgrade ingress-nginx ingress-nginx/ingress-nginx \
  --namespace ingress-nginx \
  --set controller.image.tag=1.12.1
```

**CVE-2025-1097 — runc container escape**
- **Severity**: High (CVSS 8.6)
- **Affected**: runc < 1.2.5
- **Impact**: A malicious container could escape isolation and access the host filesystem through a file descriptor leak in the runc init process.
- **Patch**: Update containerd to the latest patch release, which bundles runc 1.2.5+

**CVE-2025-10281 — ArgoCD path traversal**
- **Severity**: High (CVSS 7.5)
- **Affected**: ArgoCD < 2.13.3
- **Impact**: Path traversal in the repo server could allow reading arbitrary files from the ArgoCD server filesystem.
- **Patch**: Upgrade to ArgoCD 2.13.3+

## Tool Releases

### New Security Tools

**Tetragon 1.0 — GA Release**
Tetragon, Cilium's eBPF-based runtime security tool, reached 1.0 GA. Key features in the release:
- Kubernetes-native CRD policy management
- Real-time process kill (enforcement mode)
- Integration with Cilium identity for label-aware policies
- Hubble integration for unified observability

```bash
# Install Tetragon 1.0
helm upgrade cilium cilium/cilium \
  --namespace kube-system \
  --set tetragon.enabled=true \
  --set tetragon.grpc.enabled=true
```

See our [Falco vs Tetragon comparison](/blog/runtime-security-falco-tetragon) for a detailed feature breakdown.

**kube-bench 0.10 — CIS 1.9 Benchmark Support**
The latest kube-bench release adds support for the CIS Kubernetes Benchmark 1.9, which includes new controls for:
- Pod Security Admission (replacing Pod Security Policies)
- Seccomp profile requirements
- Network policy default deny recommendations

```bash
# Run CIS 1.9 benchmark
kube-bench --benchmark cis-1.9
```

### Notable Updates

**Falco 0.41 — New Rule Engine**
- Improved rule evaluation performance (30% faster)
- New `evt.rawres` field for system call return values
- Enhanced Kubernetes audit event support
- New community rules for cryptomining detection

**Kyverno 1.13 — Generate Policies**
- New `generateExisting` feature to apply generate policies to existing resources
- Improved policy report performance
- New `apiCall` capability for dynamic data in policies

**Trivy 0.58 — Enhanced K8s Scanning**
- New `--scanners misconfig` flag for K8s manifest scanning
- Improved SBOM generation with CycloneDX 1.6 support
- Faster image scanning with parallel layer analysis

### Deprecations

- **Pod Security Policies**: Fully removed in K8s 1.25. If you're still using PSPs, migrate to Pod Security Admission immediately.
- **kubectl auth can-i --list** without namespace: Now defaults to the current namespace instead of all namespaces. Use `--all-namespaces` explicitly.

## Policy and Standards

### CIS Updates

**CIS Kubernetes Benchmark 1.9.0 Released**
The new benchmark includes:
- Updated controls for K8s 1.29-1.31
- New section on Pod Security Admission
- Enhanced network policy recommendations
- Updated etcd encryption guidance

Key changes from 1.8.0:
- New control 5.7: "Ensure that Pod Security Admission is configured"
- Updated control 4.1: Now requires seccomp profiles by default
- Removed control 5.2 (Pod Security Policies — deprecated)

### NIST Guidance

**NIST SP 800-204D — Security Strategies for Cloud-Native Applications**
New NIST publication covering:
- Microservices security architecture patterns
- Service mesh security considerations
- Zero-trust implementation for K8s
- Supply chain security for container images

Recommended reading for anyone designing cloud-native security architecture.

### Industry Frameworks

**SOC2 Type II — Kubernetes Control Mapping Guide**
The Cloud Security Alliance released a mapping guide for SOC2 controls to K8s configurations. Key mappings:

| SOC2 Control | K8s Implementation |
|-------------|-------------------|
| CC6.1 Logical Access | RBAC + Pod Security Admission |
| CC7.1 System Monitoring | Audit logging + Falco/Tetragon |
| CC7.2 Anomaly Detection | Runtime security alerts |
| CC8.1 Change Management | GitOps with policy enforcement |

### Best Practice Reminders

- **Pin image digests**: Use `image@sha256:...` not `image:tag` for production
- **Audit RBAC monthly**: Run `rbac-lookup` and review for over-permissive roles
- **Enable audit logging**: If you haven't, enable it now — see our [hardening checklist](/blog/devsecops-hardening-checklist)
- **Review network policies**: Ensure default-deny is in place for all namespaces
- **Scan images continuously**: Don't just scan in CI — scan running images too
