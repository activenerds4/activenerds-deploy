## This Week in Models

The open-source LLM space continues to accelerate. This week saw several notable releases:

**Qwen 2.5 family** dropped with models ranging from 0.5B to 72B parameters. The 72B model claims GPT-4-level performance on reasoning benchmarks while being fully open-weight. Early community testing suggests it's particularly strong on code generation and multilingual tasks. Worth experimenting with if you need a strong model you can self-host.

**Mistral Small 3** was released — a 24B parameter model targeting the "sweet spot" between capability and deployability. It fits on a single A100 with INT4 quantization and benchmarks competitively with much larger models on practical tasks. For teams that need good-enough LLM performance without multi-GPU infrastructure, this is a strong candidate.

**Llama 3.3** received a quiet update with improved function calling and tool use. The diff is small but meaningful for anyone building agentic workflows.

<Callout type="tip">
Don't chase every model release. Pick 2-3 models that fit your deployment constraints and benchmark them on your actual tasks. Benchmark scores on standard datasets rarely predict your real-world performance.
</Callout>

## Research Highlights

**Test-time compute scaling** continues to be the hottest research direction. The key insight: spending more compute at inference time (chain-of-thought, self-consistency, search) can be more efficient than training larger models. Several papers this week extended this idea:

- **"Scaling Inference Compute Without Training"** showed that process reward models can guide inference-time search to match the performance of models 10x larger on math reasoning tasks. The implication: you may not need to train a bigger model — you need to search more efficiently at inference.

- **"Self-Improving Reasoners"** demonstrated a training loop where models generate reasoning traces, filter by correctness, and fine-tune on the good ones — improving without external data. The results on GSM8K and MATH benchmarks are impressive, though generalization to out-of-distribution tasks remains an open question.

**Mixture-of-Experts (MoE) efficiency** got attention with a paper showing that sparse MoE models can achieve 3x inference speedup over dense models of equivalent quality, but only if the routing is well-optimized. Poor routing leads to load imbalance that eliminates the speedup.

## Industry Moves

**OpenAI** announced [structured outputs](/articles/prompt-engineering-techniques-guide) API for all GPT-4o models, making it significantly easier to build reliable tool-use and data extraction pipelines. The API enforces JSON schema compliance, eliminating the need for retry logic when models produce malformed output.

**Anthropic** released Claude's computer use capability to general availability. Early adopters report it works well for simple UI automation but struggles with complex multi-step workflows. The safety implications remain actively debated.

**Google** quietly deprecated several PaLM API endpoints in favor of Gemini, continuing their consolidation. If you're still using PaLM APIs, migration is now urgent.

**Hugging Face** acquired an [inference optimization](/articles/llm-inference-optimization) startup, signaling deeper investment in making model serving faster and cheaper. The long-term play seems to be competing with Together AI and Fireworks on managed inference.

## Tools and Frameworks

**vLLM 0.6** shipped with improved continuous batching and support for AWQ-quantized models. The throughput improvements are significant — 30-40% over 0.5.x for LLM serving. If you're serving LLMs and not on the latest vLLM, update.

**Unsloth** continues to gain traction for fast fine-tuning — their 2x speedup claims for LoRA fine-tuning have been independently verified by several community members. The library now supports more model architectures and has better documentation.

**Ollama** added support for tool calling, making it more viable for local agentic workflows. Combined with the growing library of supported models, it's becoming the standard for local LLM development.
