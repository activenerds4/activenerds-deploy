[Container images](/articles/distroless-container-images-security) are the delivery vehicle for modern applications — and the delivery vehicle for vulnerabilities. A single base image can pull in hundreds of packages, each with its own CVE history. Image scanning is how you catch those vulnerabilities before they reach production.

This guide compares the four most popular [container image](/articles/container-image-registry-comparison) [scanning tools](/articles/secrets-scanning-ci-pipelines): Trivy, Grype, Snyk, and Aqua.

## Why Image Scanning Matters

### CVE Landscape

The average production container image contains 200+ known vulnerabilities. Most are in transitive dependencies — packages your direct dependencies depend on. Without a scanner, you have no visibility into this surface.

### Shift-Left Security

Catching vulnerabilities in CI is 100x cheaper than catching them in production. A scanner in your pipeline turns a post-incident fire drill into a pre-deploy checklist item.

### Compliance Requirements

SOC2, PCI-DSS, and FedRAMP all require [vulnerability scanning](/articles/vulnerability-scanning-automation-ci) of container images. The question isn't whether to scan — it's which tool to use.

## Trivy

Trivy (by Aqua Security) is the open-source standard for container image scanning. It's fast, comprehensive, and has the best developer experience of any scanner.

### Open-Source Advantage

Trivy is fully open-source (Apache 2.0), with no feature-gated tiers. You get the full scanner for free, including [SBOM generation](/articles/sbom-generation-tools-comparison), misconfiguration detection, and secret scanning.

```bash
# Scan a local image
trivy image myregistry/app:v1

# Scan with severity filter
trivy image --severity HIGH,CRITICAL myregistry/app:v1

# Generate SBOM
trivy image --format cyclonedx myregistry/app:v1 > sbom.json

# Scan for secrets in the image
trivy image --scanners secret myregistry/app:v1
```

### Scanning Speed

Trivy's Go-based scanner is fast — typically 5-15 seconds for a medium-sized image. It caches vulnerability databases locally, so subsequent scans are even faster.

### SBOM Generation

Trivy generates SBOMs in CycloneDX, SPDX, and Syft formats. This is increasingly important for supply chain compliance (SLSA, Executive Order 14028).

## Grype and Syft

Grype (by Anchore) is another open-source scanner, often paired with Syft (SBOM generator). Together they form a modular scanning pipeline.

### Anchore Ecosystem

Syft generates the SBOM; Grype matches it against the vulnerability database. This separation of concerns is cleaner than Trivy's monolithic approach, but requires two tools:

```bash
# Generate SBOM with Syft
syft myregistry/app:v1 -o cyclonedx-json > sbom.json

# Scan SBOM with Grype
grype sbom:sbom.json --fail-on high
```

### Database Updates

Grype's vulnerability database updates daily. You can configure update frequency and use an offline database for air-gapped environments:

```bash
grype db update
grype myregistry/app:v1 --db-dir /path/to/offline-db
```

### CI Integration

Grype integrates well with GitHub Actions:

```yaml
- uses: anchore/scan-action@v3
  with:
    image: myregistry/app:v1
    fail-build: true
    severity-cutoff: high
```

## Snyk and Aqua

### Commercial Features

Snyk and Aqua are commercial platforms that add remediation guidance, policy enforcement, and dashboards on top of scanning.

**Snyk** excels at developer-facing remediation. It doesn't just list vulnerabilities — it suggests version upgrades and opens PRs to fix them. Its container scanning integrates with its broader SCA, IaC, and code analysis products.

**Aqua** is enterprise-focused, with runtime protection, admission control, and compliance reporting. It's the choice for organizations that need a full container security platform, not just a scanner.

### Remediation Guidance

Snyk's standout feature is actionable fix suggestions:

```
Vulnerability: CVE-2024-1234
Package: openssl 3.1.2
Fixed in: openssl 3.1.3
Suggested action: Upgrade base image to debian:bookworm-20240901
```

This is what makes Snyk worth paying for — it reduces the time from "vulnerability found" to "vulnerability fixed" from hours to minutes.

### Policy Enforcement

Aqua and Snyk both support policy-based gating: block deploys if HIGH or CRITICAL vulnerabilities are found, with exceptions for specific CVEs that have been accepted as risks.

## Comparison Matrix

| Feature | Trivy | Grype | Snyk | Aqua |
|---------|-------|-------|------|------|
| License | Apache 2.0 | Apache 2.0 | Commercial | Commercial |
| Scanning speed | Fast (5-15s) | Fast (10-20s) | Medium | Medium |
| SBOM generation | Built-in | Via Syft | Built-in | Built-in |
| Secret scanning | Yes | No | Yes | Yes |
| Misconfig scanning | Yes | No | Yes | Yes |
| Remediation guidance | Basic | None | Excellent | Good |
| Policy enforcement | Via CI | Via CI | Built-in | Built-in |
| Runtime protection | No | No | No | Yes |
| Cost | Free | Free | Free tier + paid | Enterprise pricing |

<Callout type="info">
**Recommendation:** Start with Trivy — it's free, fast, and covers 90% of what most teams need. Move to Snyk if your team struggles with remediation workflow (fixing the vulnerabilities, not just finding them). Choose Aqua if you need runtime protection and enterprise compliance dashboards.
</Callout>

## Building a Scanning Pipeline

A practical scanning pipeline in CI:

```yaml
# .github/workflows/image-scan.yml
name: Image Security Scan
on: [push, pull_request]
jobs:
  scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Build image
        run: docker build -t app:${{ github.sha }} .
      - name: Trivy scan
        uses: aquasecurity/trivy-action@master
        with:
          image-ref: app:${{ github.sha }}
          severity: HIGH,CRITICAL
          exit-code: '1'
      - name: Generate SBOM
        uses: aquasecurity/trivy-action@master
        with:
          image-ref: app:${{ github.sha }}
          format: cyclonedx
          output: sbom.json
      - name: Upload SBOM
        uses: actions/upload-artifact@v4
        with:
          name: sbom
          path: sbom.json
```

<Callout type="tip">
**Movement break:** Vulnerability triage is cognitively heavy — each CVE requires a decision. After 20 minutes of scanning results, do the 20-20-20 rule: look at something 20 feet away for 20 seconds. Your eyes and brain need the reset before the next batch of findings.
</Callout>

## Summary

Image scanning is a baseline security practice, not an optional extra. Trivy gives you the best free option. Grype offers a modular alternative. Snyk and Aqua add remediation and policy features worth paying for when your team's remediation throughput becomes the bottleneck. Whatever you choose, integrate it into CI and fail builds on HIGH/CRITICAL findings — a scanner that doesn't block bad images is just a reporting tool.
