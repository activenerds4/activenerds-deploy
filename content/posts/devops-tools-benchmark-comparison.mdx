"Which CI/CD platform is fastest?" is the wrong question. The right question is "which tool gives the best cost-to-performance ratio for your specific workload?" A 2-minute build difference doesn't matter if you're paying 3x more. This benchmark compares the most popular DevOps tools across speed, cost, and operational overhead so you can make an informed decision.

## Benchmark Methodology

### What We Measured

Three categories of DevOps tools, each tested with identical workloads:

1. **CI/CD Runners** — build, test, and deploy a medium-sized TypeScript + Docker application
2. **Container Registries** — push and pull a 250MB image across regions
3. **IaC Execution** — plan and apply a 50-resource [Terraform](/articles/infrastructure-as-code-terraform-pulumi)/Pulumi project

### Test Environment

- **Application:** TypeScript monorepo, 15 packages, 200 tests, Docker build
- **Image:** Node 20-slim base, 250MB final image
- **IaC:** 50 AWS resources (VPC, EKS, RDS, IAM, S3)
- **Regions:** us-east-1, eu-west-1, ap-southeast-1
- **Timeframe:** 30-day average, 100 runs per test

### Workload Profiles

- **Small:** 5-minute build, single service, no Docker
- **Medium:** 10-minute build, Docker image, integration tests
- **Large:** 25-minute build, multi-arch Docker, E2E tests, IaC deploy

## CI/CD Runner Comparison

### GitHub Actions vs GitLab CI vs CircleCI

| Metric | GitHub Actions | GitLab CI | CircleCI |
|--------|---------------|----------|----------|
| Build speed (medium) | 8m 42s | 9m 15s | 7m 58s |
| Cache hit rate | 85% | 78% | 91% |
| Cost per build (medium) | $0.08 | $0.06 | $0.12 |
| Runner availability | 99.8% | 99.5% | 99.9% |
| Max parallel jobs | Unlimited (paid) | Unlimited (paid) | 80 (Performance) |
| Self-hosted runner | Yes (free) | Yes (free) | Yes (paid) |

### Build Speed Analysis

CircleCI's speed advantage comes from its Docker layer caching and automatic test parallelism. GitHub Actions is competitive when you optimize caching:

```yaml
# GitHub Actions with optimized caching
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: docker/setup-buildx-action@v3
      - uses: docker/build-push-action@v5
        with:
          context: .
          push: false
          tags: app:test
          cache-from: type=gha
          cache-to: type=gha,mode=max
      - uses: actions/cache@v4
        with:
          path: node_modules
          key: ${{ runner.os }}-node-${{ hashFiles('**/pnpm-lock.yaml') }}
```

### Cost per Build

GitHub Actions charges per minute. GitLab CI charges per minute but has lower rates. CircleCI charges per credit, which can be more expensive but includes better caching out of the box.

<Callout type="info">
For a team running 500 builds/month at the medium workload: GitHub Actions costs ~$40/month, GitLab CI ~$30/month, CircleCI ~$60/month. The cost difference is small enough that speed and DX should drive the decision, not price.
</Callout>

## Container Registry Speed

### Pull Speed Comparison

| Registry | Pull (us-east-1) | Pull (eu-west-1) | Pull (ap-southeast-1) | Geo-replication |
|----------|-----------------|-------------------|------------------------|-----------------|
| Docker Hub | 12.3s | 18.7s | 22.1s | Paid only |
| GHCR | 8.1s | 14.2s | 16.8s | No |
| ECR | 4.2s | 11.5s | 5.1s | Yes (paid) |
| GCR/Artifact Registry | 5.8s | 6.1s | 7.2s | Yes |
| Harbor (self-hosted) | 3.8s | 4.1s | 4.5s | Yes (manual) |

### Layer Caching

Registry pull speed depends heavily on layer caching. If layers are already cached on the node, pulls are nearly instant. The key is consistent base images:

```dockerfile
# Consistent base image across all services
FROM node:20-slim AS base
# This layer gets cached on every node after first pull
```

### Geo-Replication

For global teams, geo-replication matters. ECR and GCR replicate images across regions automatically. Docker Hub's geo-replication is a paid feature. Self-hosted Harbor gives you full control but requires operational effort.

## IaC Execution

### Terraform Plan Speed

| Metric | Terraform | Pulumi |
|--------|-----------|--------|
| Plan (50 resources) | 8.2s | 7.1s |
| Apply (50 resources) | 4m 15s | 3m 52s |
| State operation | 1.2s | 0.8s |
| Refresh | 12.3s | 10.1s |

### Pulumi up Timing

Pulumi's speed advantage comes from its parallel resource creation. Terraform parallelizes too, but Pulumi's language-based approach allows more intelligent dependency graphing:

```typescript
// Pulumi can express dependencies that Terraform can't easily
const vpc = new aws.ec2.Vpc("main", { cidrBlock: "10.0.0.0/16" });

// These subnets are created in parallel automatically
const subnets = zones.map((zone, i) =>
  new aws.ec2.Subnet(`subnet-${i}`, {
    vpcId: vpc.id,
    cidrBlock: `10.0.${i}.0/24`,
    availabilityZone: zone,
  })
);
```

### State Operation Overhead

Both tools store state remotely. The overhead of reading/writing state is small but adds up for large projects:

- **Terraform** — S3 backend with DynamoDB locking: ~1.2s per operation
- **Pulumi** — Pulumi Service backend: ~0.8s per operation

<Warning>
State operations are not where you should optimize. The difference between 0.8s and 1.2s is negligible compared to the 3-4 minutes of actual cloud API calls. Focus on optimizing your resource graph, not your state backend.
</Warning>

## Takeaways

### Best Tool by Workload

| Workload | Best CI/CD | Best Registry | Best IaC |
|----------|-----------|--------------|----------|
| Small team, GitHub-centric | GitHub Actions | GHCR | Terraform |
| Enterprise, multi-cloud | GitLab CI | ECR/GCR | Terraform |
| Speed-critical, Docker-heavy | CircleCI | ECR | Pulumi |
| Cost-sensitive, self-hosted | GitHub Actions (self-hosted) | Harbor | Terraform |
| Developer-heavy, K8s-focused | GitHub Actions | GHCR | Pulumi |

### Cost-Performance Ratio

The best cost-performance ratio depends on your build volume:

- **Under 100 builds/month:** Any tool is fine — pick by DX
- **100-500 builds/month:** GitHub Actions or GitLab CI — optimize caching
- **500+ builds/month:** Self-hosted runners or GitLab CI — shared runners get expensive
- **Multi-region deploys:** ECR/GCR with geo-replication — pull [speed matters](/articles/cicd-pipeline-optimization) more than price

### When Speed Isn't Everything

A 1-minute faster build is worthless if the tool is painful to use. Developer experience, ecosystem integration, and team familiarity matter more than raw speed for most teams. Pick the tool your team will actually use well.

## Summary

No single tool wins every category. GitHub Actions is the best all-rounder for GitHub-centric teams. CircleCI wins on raw speed. GitLab CI wins on cost.

ECR and GCR win on pull speed. Terraform wins on ecosystem; Pulumi wins on developer experience. Match the tool to your team's actual workload and constraints — not to what's trending on Hacker News.
