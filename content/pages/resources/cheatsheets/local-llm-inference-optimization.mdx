## 2. Ollama CLI Quick Reference

```bash
# Lifecycle
ollama pull <model>[:tag]          # Download (tag defaults to :latest)
ollama run <model>                 # Interactive chat
ollama run <model> --keepalive 30m # Stay loaded in memory 30m after idle
ollama list                        # Installed models
ollama ps                          # Currently loaded in memory
ollama rm <model>                  # Delete
ollama stop <model>                # Unload from RAM without deleting

# Common tags (quantization baked into the tag)
ollama run llama3.1:8b-instruct-q4_K_M
ollama run qwen2.5:14b-instruct-q5_K_M
ollama run deepseek-r1:14b
```

```dockerfile
FROM llama3.1:8b-instruct-q4_K_M

PARAMETER top_p 0.9
PARAMETER repeat_penalty 1.1
```

## 3. Quantization Formats

Quantization shrinks weights from FP16 (16-bit) to lower precision, trading a little accuracy for big memory savings.

    { label: "Q4_K_M", values: ["4-bit", "~4.5 GB", "Good", "Sweet spot for 8B on 8GB VRAM"] },
    { label: "Q4_0", values: ["4-bit", "~4.3 GB", "Acceptable", "Max compression, older format"] },
    { label: "Q3_K_M", values: ["3-bit", "~3.5 GB", "Degraded", "Desperate / tiny GPU"] },
  ]}
/>

### GGUF vs AWQ vs GPTQ

| Format | Where it runs | Notes |
|--------|---------------|-------|
| **GGUF** | llama.cpp, Ollama, CPU+GPU mix | Most flexible; partial GPU offload via `-ngl` |
| **AWQ** | vLLM, HF Transformers | Activation-aware; fast on GPU, no CPU path |
| **GPTQ** | vLLM, AutoGPTQ | Older 4-bit GPU format; largely superseded by AWQ |
| **EXL2** | ExLlamaV | Variable bitrate; great for single-user GPU chat |

<Callout variant="tip" title="Default recommendation">
Start with **Q4_K_M** GGUF for local single-user use. Drop to Q3 only if you're VRAM-starved, and step up to Q6_K if you have room and care about quality. For multi-user GPU serving, use **AWQ** through vLLM.
</Callout>

## 4. Context Window & Memory Math

The single most useful formula for local inference:

```text
VRAM (GB) ≈ (params in B × bytes per param) + (context tokens × bytes per KV token)
```

### Weight memory by quantization

```text
FP16  : params × 2.0  bytes   (8B → 16 GB)
Q8    : params × 1.0  bytes   (8B →  8 GB)
Q4    : params × 0.55 bytes   (8B → 4.4 GB)
```

### KV cache memory (the part people forget)

```text
KV cache ≈ 2 × num_layers × hidden_size × kv_heads × ctx_tokens × bytes_per_elem
```

Practical rule of thumb (FP16 KV cache):

```text
KV per token ≈ 0.5–2 MB/token  (depends on model)
8K context  ≈ 4–16 GB extra KV memory on a 7–8B model
```

<Callout variant="warning" title="Context is not free">
Doubling the context window can double total VRAM use because the KV cache grows linearly with tokens. A model that fits at 4K context may OOM at 32K. Use **KV cache quantization** (`--kv-cache-dtype fp8` in vLLM, `--cache-type q8_0` in llama.cpp) to roughly halve this.
</Callout>

### Worked example: 8B Q4 at 8K context

```text
Weights : 8 × 0.55          ≈ 4.4 GB
KV cache: ~1 MB × 8192      ≈ 8.2 GB  (FP16)
Total   :                    ≈ 12.6 GB  → needs a 16 GB GPU
With Q8 KV cache:            ≈ 8.5 GB   → fits on 12 GB GPU
```

## 5. vLLM Serving

For real throughput (batched requests, continuous batching, paged attention):

```bash
# Basic serve
vllm serve meta-llama/Meta-Llama-3.1-8B-Instruct \
  --dtype auto \
  --max-model-len 8192 \
  --gpu-memory-utilization 0.9

# AWQ quantized model
vllm serve TheBloke/Llama-3-8B-Instruct-AWQ \
  --quantization awq \
  --max-model-len 8192

# Multi-GPU tensor parallel
vllm serve <model> --tensor-parallel-size 2

# Speculative decoding (draft model proposes, main model verifies)
vllm serve <model> \
  --speculative-model meta-llama/Llama-3.2-1B-Instruct \
  --num-speculative-tokens 5
```

### Key flags

| Flag | Purpose |
|------|---------|
| `--max-model-len` | Cap context; lower it to save VRAM |
| `--gpu-memory-utilization` | Fraction of VRAM to use (default 0.9) |
| `--enforce-eager` | Disable CUDA graphs (lower mem, slower) |
| `--kv-cache-dtype fp8` | Halve KV cache memory |
| `--tensor-parallel-size N` | Split across N GPUs |
| `--quantization awq\|gptq\|fp8` | Load quantized weights |
| `--enable-prefix-caching` | Cache shared prompt prefixes (huge for RAG) |

<Callout variant="tip" title="Prefix caching for RAG">
Enable `--enable-prefix-caching` when serving RAG workloads. Repeated system prompts and shared document chunks hit the cache instead of re-computing — often 2–5× faster TTFT.
</Callout>

## 6. CPU / Metal vs GPU Offloading

### llama.cpp / Ollama GPU offload

```bash
# -ngl = number of layers offloaded to GPU. 0 = pure CPU, 99 = all layers.
./llama-server -m model.gguf -c 8192 -ngl 33      # offload 33 layers
./llama-server -m model.gguf -c 8192 -ngl 0       # CPU only
./llama-server -m model.gguf -c 8192 -ngl 99      # full GPU (if it fits)
```

Ollama auto-detects and offloads as many layers as fit; check with `ollama ps`.

<Callout variant="note" title="Apple Silicon is a sleeper hit">
An M2/M3/M4 Max with 64 GB unified memory can run a 70B Q4 model that would need two 80GB datacenter GPUs. Memory bandwidth (not just size) is the real bottleneck — Apple's 400+ GB/s is why Metal punches above its weight.
</Callout>

### CPU-only tuning (when you have no GPU)

```bash
./llama-server -m model.gguf -c 4096 -ngl 0 \
  --threads $(nproc) \
  --mlock               # pin model in RAM (no swap)
  --no-mmap             # load fully into RAM (faster, uses more)
```

## 7. Model Selection Heuristics

<ChecklistBox title="Choosing a local model" items={[
  "1️⃣ **Check VRAM**: `nvidia-smi` or Activity Monitor. This is your hard ceiling.",
  "2️⃣ **Pick quantization**: Q4_K_M default. Q6_K if you have headroom. Q3 only if desperate.",
  "3️⃣ **Size the context**: Start at 4K–8K. Raise only if the task needs it (long docs). Watch KV cache.",
  "4️⃣ **Choose runtime**: Ollama for dev, vLLM for serving, llama.cpp for control.",
  "5️⃣ **Benchmark**: Measure tokens/sec and TTFT with `ollama run --verbose` or vLLM metrics.",
  "6️⃣ **Offload**: Set `-ngl` as high as fits. If it swaps, you've lost — lower context or quant."
]} />

### Quick capacity guide (Q4_K_M, 8K context, single user)

| GPU VRAM | Max model size (comfortable) |
|----------|------------------------------|
| 8 GB | 7B–8B |
| 12 GB | 8B (roomy) / 14B (tight) |
| 16 GB | 14B / 32B (tight, low context) |
| 24 GB | 32B / 70B (Q3, low context) |
| 2× 80 GB | 70B Q6 with full 32K context |

<Callout variant="warning" title="The swap trap">
If total memory exceeds VRAM and the OS pages to system RAM or disk, throughput collapses from tokens/sec to tokens/minute. Always size so weights + KV cache fit in VRAM. When in doubt, lower the context window first — it's the cheapest lever.
</Callout>
