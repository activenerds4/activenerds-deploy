## 1. The Diagnostic Hierarchy

Always investigate in this order. Skipping steps sends you down rabbit holes.

<ChecklistBox title="Debugging order" items={[
  "1️⃣ **Events**: `kubectl get events -A --sort-by='.lastTimestamp'` — what does the cluster think happened?",
  "2️⃣ **Describe**: `kubectl describe pod <name>` — read the Events section at the bottom",
  "3️⃣ **Logs**: `kubectl logs <pod>` then `--previous` if it crashed",
  "4️⃣ **Spec**: `kubectl get pod <name> -o yaml` — is the actual spec what you expect?",
  "5️⃣ **Node**: `kubectl describe node <node>` — resource pressure, conditions, taints"
]} />

```bash
# The one-liner that starts every investigation
kubectl get events -A --sort-by='.lastTimestamp' | tail -30

# Or scoped to a namespace, most recent first
kubectl get events -n <ns> --sort-by='.lastTimestamp' --field-selector type!=Normal
```

<Callout variant="tip" title="Events expire">
Events are garbage-collected (default 1 hour). If you're investigating a crash that happened hours ago, events may be gone — rely on `describe` and logs instead. Set up log aggregation so you always have history.
</Callout>

## 2. Pod Lifecycle & States

```bash
kubectl get pods -A -o wide
kubectl get pods -A --field-selector status.phase!=Running
kubectl describe pod <name>
```

| State | Meaning | First Check |
|-------|---------|-------------|
| `Running` | Container(s) running | `kubectl logs` |
| `Pending` | Not scheduled | `describe` → Events (resources? taints? PVCs?) |
| `Failed` | Container exited non-zero | `logs --previous` |
| `CrashLoopBackOff` | Keeps crashing, backing off | [§3](#3-crashloopbackoff) |
| `OOMKilled` | Killed for exceeding memory limit | [§4](#4-oomkilled) |
| `ImagePullBackOff` | Can't pull image | [§5](#5-imagepullbackoff) |
| `Evicted` | Kicked off node for pressure | Node pressure; requests/limits |
| `Completed` | Ran to finish (Job) | Exit code, logs |

### Container restart counts

```bash
# Restart count tells you how many times it crashed
kubectl get pods -o custom-columns=NAME:.metadata.name,RESTARTS:.status.containerStatuses[0].restartCount,STATUS:.status.phase

# High restart count + Running = it's flapping. Check logs --previous.
```

## 3. CrashLoopBackOff

The pod starts, crashes, Kubernetes retries with exponential backoff. The fix depends on *why* it crashes.

```bash
# 1. Get the crash reason from events
kubectl describe pod <name> | grep -A 20 "Events:"

# 2. Get the crashed container's exit log (the gold command)
kubectl logs <name> --previous

# 3. See the exit code
kubectl get pod <name> -o jsonpath='{.status.containerStatuses[0].lastState.terminated.exitCode}'
```

### Common causes

| Exit code | Likely cause | Fix |
|-----------|--------------|-----|
| `1` | App error / config | Read `logs --previous` |
| `137` | OOMKilled or SIGKILL | [§4](#4-oomkilled) |
| `139` | Segfault | Bad binary / arch mismatch |
| `143` | SIGTERM (graceful) | Expected on shutdown |
| `126` | Permission denied | Exec bit / rootless user |

<Callout variant="warning" title="Check the liveness probe">
A common CrashLoopBackOff cause: the liveness probe fires before the app is ready and kills a slow-starting container. If `logs --previous` shows healthy startup that gets cut off, raise `initialDelaySeconds` or add a `startupProbe`.
</Callout>

### Debug a crashing image interactively

```bash
# Run the same image with an override that keeps it alive
kubectl run debug --image=<same-image> -it --rm \
  --command -- /bin/sh

# Or override the entrypoint to a shell
kubectl run debug --image=<same-image> -it --rm --overrides='{
  "spec": {"containers": [{"name":"debug","image":"<same-image>","command":["/bin/sh"],"stdin":true,"tty":true}]}
}' -- /bin/sh
```

## 4. OOMKilled

The container exceeded its memory `limit` and the kernel killed it. `requests` don't cause OOM — `limits` do.

```bash
# Confirm OOMKilled
kubectl describe pod <name> | grep -i "oom\|killed"
kubectl get pod <name> -o jsonpath='{.status.containerStatuses[0].lastState.terminated.reason}'
# → "OOMKilled"

# Check the limit that was set
kubectl get pod <name> -o jsonpath='{.spec.containers[0].resources}'
```

### The fix decision tree

```text
Is the OOM from a memory leak or a real workload spike?
├── Leak       → fix the app; a higher limit just delays the crash
└── Spike      → raise the limit, OR tune the app (JVM heap, batch size)
```

```yaml
# Raise the limit (and request proportionally)
resources:
  requests:
    memory: "512Mi"
  limits:
    memory: "1Gi"      # was 512Mi — too tight
```

<Callout variant="tip" title="Watch JVM/Python heap">
For JVM apps, set `-XX:MaxRAMPercentage=75` so the heap stays under the container limit (leaving room for off-heap). For Python, memory grows with data — cap batch sizes. A container limit can't fix a process that genuinely needs more RAM.
</Callout>

### Node-level memory pressure

```bash
# If the NODE is under pressure, it evicts pods
kubectl describe node <node> | grep -A 5 "MemoryPressure\|DiskPressure"

# Kubelet evicts when memory exceeds hard eviction threshold (~90%)
# Fix: rebalance pods, add nodes, or lower per-pod requests
```

## 5. ImagePullBackOff

The kubelet can't fetch the image. Check in this order:

```bash
# 1. Exact error
kubectl describe pod <name> | grep -A 5 "Failed\|Error"

# 2. Common causes:
#    - Wrong image name / tag
#    - Private registry without imagePullSecrets
#    - imagePullPolicy: Always on a rate-limited registry (Docker Hub)
#    - Network egress blocked
```

### Fixes

```yaml
# Private registry: add a pull secret
spec:
  imagePullSecrets:
    - name: regcred
# Created via:
# kubectl create secret docker-registry regcred \
#   --docker-server=ghcr.io --docker-username=... --docker-password=...

# Avoid Docker Hub rate limits: pin a digest, use IfNotPresent
spec:
  containers:
    - image: myapp@sha256:abc123...   # pin digest for reproducibility
      imagePullPolicy: IfNotPresent
```

<Callout variant="note" title="imagePullPolicy defaults">
`Always` if tag is `:latest`; `IfNotPresent` otherwise. If you're hitting rate limits on Docker Hub, either pin to a digest with `IfNotPresent` or mirror to your own registry. Never use `:latest` in production.
</Callout>

## 6. kubectl debug & Ephemeral Containers

When a pod is crash-looping or has no shell (`distroless`), inject a temporary debug container into the running pod.

### Debug a distroless / shell-less pod

```bash
# Inject an ephemeral debug container (busybox) into the target pod
kubectl debug -it <pod-name> --image=busybox:1.36 --target=<container-name>

# Copy the target pod with a debug container added (doesn't touch the original)
kubectl debug -it <pod-name> --image=busybox:1.36 --copy-to=<pod-name>-debug --share-processes
```

### Debug a node

```bash
# Spin up a privileged pod on the node with the node's filesystem mounted
kubectl debug node/<node-name> -it --image=ubuntu:22.04
# Inside: chroot /host to inspect the node's filesystem
```

### Debug a crashed pod by copying it

```bash
# Copy the pod, change the command to keep it alive, debug
kubectl debug <pod-name> -it \
  --copy-to=<pod-name>-debug \
  --set-image=*=ubuntu:22.04 \
  -- /bin/bash
```

<Callout variant="tip" title="Ephemeral containers are a lifesaver for distroless">
Distroless images have no shell — you can't `kubectl exec` into them. `kubectl debug` injects a sidecar with tools, sharing the network namespace so you can inspect the distroless container's processes and network. This is the supported way to debug minimal images.
</Callout>

### Profile a running pod

```bash
# Copy a pod and run profiling tools without touching production
kubectl debug <pod-name> --copy-to=<pod-name>-profile \
  --image=nicolaka/netshoot -it -- /bin/sh
# netshoot has curl, tcpdump, dig, nslookup, mtr, strace...
```

## 7. Drain, Taint & Incident Response

### Drain a node safely (evict all pods)

```bash
# Standard drain — evicts pods, ignores DaemonSets, cleans emptyDirs
kubectl drain <node> --ignore-daemonsets --delete-emptydir-data

# If pods have PDBs that block eviction, check first
kubectl get poddisruptionbudgets -A

# Force if you must (bypasses PDBs — use only in emergencies)
kubectl drain <node> --ignore-daemonsets --delete-emptydir-data --disable-eviction

# Bring it back
kubectl uncordon <node>
```

<Callout variant="warning" title="Drain can hang">
`kubectl drain` blocks if a PodDisruptionBudget isn't satisfied (not enough replicas to evict safely). If you're in an emergency and the PDB is wrong, `--disable-eviction` forces deletion — but you may cause an outage. Fix the PDB afterward.
</Callout>

### Taints & tolerations

```bash
# See taints on all nodes
kubectl get nodes -o custom-columns=NAME:.metadata.name,TAINTS:.spec.taints

# Taint a node (repels pods without a matching toleration)
kubectl taint nodes <node> key=value:NoSchedule

# Taint for maintenance (also evicts running pods)
kubectl taint nodes <node> key=value:NoExecute

# Remove a taint (trailing dash)
kubectl taint nodes <node> key=value:NoSchedule-
```

| Effect | Behavior |
|--------|----------|
| `NoSchedule` | Don't schedule new pods here |
| `PreferNoSchedule` | Try to avoid, but allow |
| `NoExecute` | Evict existing pods + block new |

### Incident response sequence

<ChecklistBox title="Node failure incident response" items={[
  "1️⃣ **Confirm**: `kubectl get nodes` — is the node `NotReady`?",
  "2️⃣ **Cordon**: `kubectl cordon <node>` — stop new pods scheduling there.",
  "3️⃣ **Assess**: `kubectl describe node <node>` — why did it fail?",
  "4️⃣ **Drain**: `kubectl drain <node> --ignore-daemonsets --delete-emptydir-data` — evict workloads.",
  "5️⃣ **Verify**: `kubectl get pods -A -o wide --field-selector spec.nodeName=<node>` — all gone?",
  "6️⃣ **Fix/Replace**: repair the node or replace it; then `kubectl uncordon <node>`."
]} />

<Callout variant="tip" title="Cordon before you drain">
Always `cordon` first. It marks the node unschedulable so the autoscaler doesn't immediately schedule new pods onto a node you're about to drain. Drain then evicts the existing workloads. This two-step prevents thrash.
</Callout>
