## 1. AWS KMS and Encryption at Rest

| Key type | Control | Rotation | Cost |
|---|---|---|---|
| AWS owned | Hidden, shared | AWS-managed | Free |
| **AWS managed** (`aws/s3`, `aws/ebs`) | Visible, policy not editable | Automatic yearly | Free key, pay for use |
| **Customer managed (CMK)** | Your key policy, grants, enable/disable | Optional automatic (default 365 days, configurable) or manual | Monthly + use |
| Imported material | You supply | Manual only | |

* A **key policy is mandatory** and the primary authorization mechanism. IAM policies work only if the key policy allows IAM (the default policy delegates to IAM via the account root principal). **Grants** give temporary delegated access (EBS, RDS use them).
* **Envelope encryption:** KMS encrypts a **data key** (`GenerateDataKey`), the data key encrypts data (limit of 4 KB direct `Encrypt`).
* **Key deletion** has a 7 to 30 day waiting period (disable first as a safer step). **Multi-Region keys** share key material for cross-Region decrypt.

| Service | Encryption detail |
|---|---|
| **EBS** | Encryption at creation; enable **default EBS encryption** per Region. Encrypt an existing volume by snapshot, **copy snapshot with encryption**, create volume |
| **RDS/Aurora** | Choose at creation. To encrypt an existing DB: snapshot, copy encrypted, restore. Read replicas match source |
| **S3** | **SSE-S3 is the default** for new objects; SSE-KMS adds audit and key control (use **S3 Bucket Keys** to cut KMS request cost); SSE-C client supplies keys; enforce with bucket policy |
| **EFS/FSx/DynamoDB** | At-rest encryption (DynamoDB always on; EFS at creation) |
| CloudWatch Logs, SNS, SQS | Optional CMK |

<AccordionGroup type="single">
<AccordionItem title="Deep-Dive: Troubleshooting KMS access failures">

* `AccessDeniedException` / `KMSInvalidStateException`: check key **state** (disabled, pending deletion).
* **Cross-account** use needs the key policy to allow the other account and an IAM policy in that account allowing the KMS actions. Sharing an encrypted EBS snapshot or AMI requires a **customer managed key** shared with the recipient (AWS managed keys cannot be shared).
* A service role (for example Lambda execution role reading an encrypted object) needs `kms:Decrypt`; S3 uploads with SSE-KMS need `kms:GenerateDataKey`.
* High-volume S3 SSE-KMS workloads can hit KMS **request quotas**; use Bucket Keys.
* CloudTrail logs every KMS call, so look for `errorCode` and the caller identity.

</AccordionItem>
</AccordionGroup>

```bash
aws kms create-key --description "app data" --key-spec SYMMETRIC_DEFAULT
aws kms enable-key-rotation --key-id <key-id>
aws ec2 enable-ebs-encryption-by-default
aws ec2 copy-snapshot --source-region us-east-1 --source-snapshot-id snap-0abc --encrypted --kms-key-id alias/app
```

## 2. Encryption in Transit

* **AWS Certificate Manager (ACM):** free public certificates for integrated services (ELB, CloudFront, API Gateway); **auto-renewal** (DNS validation with the CNAME record kept in place is the most reliable); private CA available separately. By default ACM public certificate private keys cannot be exported.
* **Regional scope:** a certificate must exist in the **same Region as the ALB/NLB**; certificates for **CloudFront** must be requested in **us-east-1**.
* **Enforce TLS:** S3 bucket policy deny when `aws:SecureTransport` is false; RDS `rds.force_ssl` parameter (PostgreSQL/SQL Server); CloudFront viewer protocol policy (redirect HTTP to HTTPS); ALB listener redirect 80 to 443; choose modern **ELB security policies**; Redis TLS (in-transit encryption).
* Validation stuck "pending": missing DNS CNAME or email not approved. Expired or mismatched certificates on EC2 instances are **not** renewed by ACM since they cannot be installed on EC2 directly.

## 3. Secrets Management

| Feature | Secrets Manager | Parameter Store SecureString |
|---|---|---|
| Automatic rotation | **Yes** (Lambda; managed for RDS, Redshift, DocumentDB) | No native rotation |
| Cost | Per secret per month + API calls | Standard tier free |
| Cross-Region replication | Yes | No |
| Size | 64 KB | 4 KB / 8 KB |
| Resource policies | Yes | No (IAM only) |

Rule of thumb: **rotation or cross-account/DB credentials means Secrets Manager**; plain configuration or low-cost secrets means Parameter Store. Never place secrets in code, AMIs, Lambda environment variables unencrypted, or user data in clear text.

```bash
aws secretsmanager create-secret --name prod/db --secret-string '{"username":"app","password":"..."}'
aws secretsmanager rotate-secret --secret-id prod/db --rotation-lambda-arn <arn> --rotation-rules AutomaticallyAfterDays=30
```

## 4. Data Classification

* Define classes (public, internal, confidential, restricted) and enforce with **tags** on resources and S3 object tags; enforce required tags with Config rules and tag policies.
* **Amazon Macie** discovers sensitive data (PII, credentials) in S3 with managed and custom identifiers and produces findings to Security Hub/EventBridge.
* Link classification to controls: encryption with CMKs for restricted data, restricted bucket policies, backup vault lock, logging.

---

## 5. Exam Traps & Common Distractors

- **Trap 1:** Trying to encrypt an existing unencrypted **RDS instance** in place. Use snapshot copy then restore.
- **Trap 2:** Requesting a CloudFront certificate in the application's Region instead of **us-east-1**.
- **Trap 3:** Sharing an encrypted snapshot encrypted with the **AWS managed key**.
- **Trap 4:** Storing database passwords in Parameter Store when **automatic rotation** is required.
- **Trap 5:** Assuming IAM permission alone allows KMS use; the **key policy** must allow it.

## Self-Assessment & Exam Traps Checklist

- [ ] I can encrypt an existing unencrypted EBS volume or RDS database.
<details>
<summary>Explanation</summary>

EBS: snapshot, copy snapshot with encryption, create volume, swap. RDS: snapshot, copy with encryption (specify KMS key), restore from the encrypted snapshot and cut over. Turn on default EBS encryption to prevent recurrence.

</details>

- [ ] I can share an encrypted AMI with another account.
<details>
<summary>Explanation</summary>

Ensure the AMI snapshots use a customer managed key, share the AMI launch permission and the underlying snapshots with the account, and grant that account use of the key via key policy (or grants). The recipient can copy the AMI and re-encrypt with its own key.

</details>

- [ ] I know why the website certificate does not appear in the CloudFront console.
<details>
<summary>Explanation</summary>

CloudFront only lists ACM certificates in **us-east-1**. Request or import the certificate there; ALB certificates must be in the load balancer's Region.

</details>

- [ ] I can pick Secrets Manager versus Parameter Store.
<details>
<summary>Explanation</summary>

Secrets Manager for credentials needing automated rotation, replication, resource policies. Parameter Store for configuration values and inexpensive encrypted parameters with hierarchical paths and IAM control.

</details>
