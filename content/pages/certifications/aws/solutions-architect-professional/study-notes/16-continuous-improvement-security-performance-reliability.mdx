**Audience:** Candidates preparing for the AWS Certified Solutions Architect - Professional (SAP-C02)
**Scope:** Least privilege audits, secrets rotation, patch pipelines, vulnerability response, KPI-driven performance tuning and single-point-of-failure remediation.

<Callout variant="info" title="Exam Blueprint Focus: Tasks 3.2, 3.3 and 3.4 Improving Existing Solutions">
You are handed an existing architecture and asked how to make it more secure, faster or more reliable with the least disruption. The skill is diagnosing the weakest link, then choosing the smallest managed change that fixes it.
</Callout>

## 1. Improvement Review Workflow

```
 1. Measure   : CloudWatch, X-Ray, Trusted Advisor, Compute Optimizer, Config, Security Hub, Well-Architected Tool
 2. Identify  : bottleneck, single point of failure, over-permission, unpatched fleet, unencrypted data
 3. Prioritize: risk x impact x effort (fix critical security and SPOFs first)
 4. Remediate : IaC change, managed service adoption, automation
 5. Verify    : re-measure against KPI, run drills, track in backlog
```

The **AWS Well-Architected Tool** records workload reviews against the pillars, flags high-risk issues and tracks improvement plans; Trusted Advisor gives checks across cost, performance, security, fault tolerance, service limits and operational excellence.

## 2. Security Hardening

**Secrets and credentials**

| Problem | Fix |
|---|---|
| Hardcoded credentials or access keys on instances | IAM roles for EC2/ECS/Lambda (instance profile, task role, execution role) |
| Plaintext database passwords in code/env vars | Secrets Manager with automatic rotation (Lambda rotation functions, native for RDS/Aurora/Redshift/DocumentDB) and cross-Region replication; or Parameter Store SecureString for static values |
| Long-lived IAM user keys | Identity Center/federation, short-lived STS credentials, rotate/disable unused keys (credential report, Access Analyzer unused access) |
| Shared admin accounts | Individual identities, MFA, break-glass role with alerting |

**Secrets Manager vs Parameter Store:** Secrets Manager costs per secret, offers native rotation, cross-account sharing and replication; Parameter Store is free for Standard parameters (4 KB), Advanced up to 8 KB, no native rotation, good for configuration and cheap secrets.

**Least privilege audit loop:** Access Analyzer external access findings, unused access findings, policy validation, policy generation from CloudTrail, IAM Last Accessed information, credential report, permissions boundaries, SCP guardrails, removal of wildcard actions/resources.

**Security at every layer:** edge (CloudFront, WAF, Shield), network (SGs, NACLs, Network Firewall, private subnets, endpoints), compute (Inspector, patching, IMDSv2 enforcement), application (Cognito, input validation), data (KMS, Macie, backups), identity, and detection/response (GuardDuty, Security Hub, Detective).

**Traceability of users and services:** CloudTrail (organization trail, data events, Lake), IAM role session names/source identity, VPC Flow Logs, ELB access logs, S3 server access logs/CloudTrail data events, Config history.

```bash
aws ec2 modify-instance-metadata-options --instance-id i-0abc --http-tokens required --http-endpoint enabled
aws secretsmanager rotate-secret --secret-id prod/db --rotation-lambda-arn arn:aws:lambda:...:function:rotator --rotation-rules AutomaticallyAfterDays=30
aws accessanalyzer create-analyzer --analyzer-name org --type ORGANIZATION
aws ssm create-patch-baseline --name prod-linux --operating-system AMAZON_LINUX_2023 --approval-rules file://rules.json
```

## 3. Patch and Update Process

| Pattern | When |
|---|---|
| Systems Manager Patch Manager + maintenance windows | Mutable fleets (EC2, on-premises); baselines per OS, patch groups by tag, scan then install, compliance dashboard |
| Immutable replacement | Build a new AMI with **EC2 Image Builder** (pipelines with tests, scheduled) and roll via Auto Scaling instance refresh or blue/green |
| Containers | Rebuild images from patched base, ECR scanning and Inspector, redeploy through pipelines |
| Managed services | RDS/Aurora maintenance windows, minor version auto-upgrade, Lambda managed runtimes, Fargate platform updates |
| Vulnerability-driven | Inspector findings -> Security Hub -> EventBridge -> SSM Automation to patch out-of-cycle |

<Callout variant="warning" title="Exam Trap">
"Reduce patching overhead" usually points to a managed service (RDS, Fargate, Lambda, Beanstalk managed updates). "Keep compliance with organizational patch standards for EC2" points to Patch Manager with baselines and compliance reporting. "Patch with no downtime" suggests immutable AMI replacement behind a load balancer.
</Callout>

## 4. Backup Process Improvements

AWS Backup plans via Organizations backup policies; cross-account/Region copies; Vault Lock; restore testing; align retention with data regulatory requirements; classify data with Macie; apply S3 versioning + Object Lock; PITR for DynamoDB/RDS; verify restoration regularly (Module 06).

## 5. Reliability Remediation: Finding and Fixing SPOFs

| Finding | Remediation |
|---|---|
| Single EC2 instance | Auto Scaling group across 3 AZs behind a load balancer; if stateful, EBS snapshot + auto recovery or migrate to managed service |
| Single-AZ database | RDS Multi-AZ / Aurora with replicas; DR cross-Region |
| One NAT gateway for all AZs | NAT per AZ |
| Single VPN tunnel/DX | Two tunnels, DX + VPN backup, maximum-resiliency DX |
| Tight synchronous coupling | SQS/SNS/EventBridge decoupling, retries with backoff |
| No health checks | ELB and Route 53 health checks, ASG replacement |
| Manual failover | Automated failover (Route 53, ARC, Global Accelerator) |
| Quota exhaustion risk | Service Quotas alarms and increases |
| Growth trend ignoring capacity | Use CloudWatch metrics, forecasts, predictive scaling, Cost Explorer usage trends |

Enable **self-healing and elastic features:** ASG health checks, EC2 auto recovery, ECS/EKS service schedulers replacing failed tasks/pods, Lambda retries/DLQs, S3/DynamoDB built-in multi-AZ.

## 6. Performance Improvement Workflow

1. Translate requirements to metrics (latency percentiles, throughput, error rate).
2. Establish a baseline and find the constraint (Module 12 bottleneck table).
3. Test remediation candidates in a staging copy using load testing; compare to baseline.
4. Adopt newer instance types (Graviton, current generation), managed services (Aurora, DynamoDB, ElastiCache), edge services (CloudFront, Global Accelerator).
5. Rightsize: Compute Optimizer recommendations, instance fleets, scaling policies.
6. Define SLAs/KPIs and alarm on them.

<AccordionGroup type="single">
<AccordionItem title="Deep-Dive: Rotating Database Credentials Without Downtime">

Secrets Manager rotation uses a Lambda function with four steps (createSecret, setSecret, testSecret, finishSecret) and the staging labels AWSCURRENT and AWSPENDING. The alternating-users strategy keeps one user valid while the other is rotated, so applications that cache credentials continue working. Applications must fetch the secret at connection time (or via the caching client), not embed it.

</AccordionItem>
<AccordionItem title="Deep-Dive: Enforcing IMDSv2 and Other Preventive Baselines">

IMDSv2 (session-token based) mitigates SSRF credential theft. Enforce through launch templates (HttpTokens required), AMI defaults, an SCP or declarative policy requiring IMDSv2, and Config/Security Hub checks. Similarly enforce EBS default encryption, S3 Block Public Access and restricted security groups using preventive controls first, detective controls second.

</AccordionItem>
</AccordionGroup>

## 7. Common Traps & Distractors

- "Rotate RDS password automatically": Secrets Manager rotation.
- "Find unused IAM permissions": Access Analyzer unused access / last accessed data.
- "Which instances need patches, report compliance": Patch Manager compliance, Inspector for CVEs.
- "Application is sluggish with a few hundred idle connections to the DB": RDS Proxy/pooling, not larger DB blindly.
- "Make an existing single-instance app highly available": Auto Scaling group + ELB across AZs, externalize state.

## Self-Assessment & Exam Traps Checklist

- [ ] I can audit an environment for least privilege.
<details>
<summary>Explanation</summary>

Use IAM Access Analyzer (external and unused access findings, policy validation, generated policies), credential reports and last-accessed data, review wildcard policies, apply permission boundaries and SCPs, remove unused roles/keys, and monitor changes with CloudTrail and Config.

</details>

- [ ] I can choose between Secrets Manager and Parameter Store.
<details>
<summary>Explanation</summary>

Use Secrets Manager when native rotation, cross-account sharing or replication is needed. Use Parameter Store for configuration and inexpensive static secrets where rotation is not required.

</details>

- [ ] I can design a patch process for mutable and immutable fleets.
<details>
<summary>Explanation</summary>

Mutable: Patch Manager baselines, patch groups and maintenance windows with compliance reports. Immutable: Image Builder pipeline producing tested AMIs, deployed via instance refresh or blue/green with rollback.

</details>

- [ ] I can systematically remove single points of failure from an existing design.
<details>
<summary>Explanation</summary>

Inventory each tier and dependency, ensure at least two AZs per tier, replace single instances with Auto Scaling groups, use Multi-AZ or Aurora for databases, redundant network paths, decouple with queues, automate failover and test with drills, and monitor quotas.

</details>
