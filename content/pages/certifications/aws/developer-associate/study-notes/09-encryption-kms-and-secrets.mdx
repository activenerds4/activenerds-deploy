<AccordionGroup type="single">
<AccordionItem title="Deep-Dive: Envelope Encryption">

KMS can directly encrypt only **4 KB** of data. For larger data, use **envelope encryption**:

1. Call **`GenerateDataKey`** on a KMS key. KMS returns a **plaintext data key** and the **same key encrypted** under the KMS key.
2. Encrypt your data locally with the plaintext data key (AES-GCM), then **discard the plaintext key** from memory.
3. Store the **encrypted data key alongside the ciphertext**.
4. To decrypt: call **`Decrypt`** on the encrypted data key (KMS verifies permission), then decrypt the data locally.

```
Plaintext data ─AES with data key─> Ciphertext ─┐
Data key ─KMS key─> Encrypted data key ─────────┴─> store together
```

* **Primary Trade-off:** Local encryption keeps big data off the KMS API (faster, cheaper) while KMS still controls and audits key use.
* **Exam Trap:** "Encrypt a 1 GB file with KMS" → envelope encryption using `GenerateDataKey` (or the AWS Encryption SDK, which does it for you), **never** a direct `Encrypt` call.

</AccordionItem>
</AccordionGroup>

## 1. Encryption at Rest and in Transit (Skills 2.2.1 and 2.2.3)

| Layer | How |
|---|---|
| **In transit** | **TLS** everywhere: HTTPS endpoints (AWS APIs already use TLS), ACM certificates on ALB/CloudFront/API Gateway, `rds.force_ssl` for RDS PostgreSQL, enforce with the `aws:SecureTransport` condition in bucket policies |
| **At rest** | Provided by most services using KMS: S3, EBS, RDS/Aurora, DynamoDB (always on), SQS, SNS, Secrets Manager, CloudWatch Logs, Lambda environment variables |

### Server-Side vs Client-Side Encryption

| Option | Who Encrypts | Keys | Choose When |
|---|---|---|---|
| **SSE-S3** | S3 | S3-managed (default for all new objects) | Simplest, no audit needs |
| **SSE-KMS** | S3 | **KMS key** (AWS managed or customer managed) | Need key-usage audit in CloudTrail, key policies, rotation control |
| **DSSE-KMS** | S3 | Two layers of encryption with KMS | Compliance requiring dual-layer |
| **SSE-C** | S3 | **Customer supplies the key on every request** (HTTPS only; S3 does not store it) | You must hold keys yourself but let S3 do the work |
| **Client-side** | **Your application** before upload | AWS Encryption SDK, S3 Encryption Client, KMS data keys | AWS must never see plaintext; end-to-end protection |

**SSE-KMS caveat:** every request calls KMS, which can hit **KMS request quotas** (throttling) at high S3 request rates. Enable **S3 Bucket Keys** to cut KMS calls dramatically. The caller needs **both S3 permissions and `kms:Decrypt`/`kms:GenerateDataKey`** on the key.

## 2. AWS KMS (Skill 2.2.4)

| Key Type | Managed By | Rotation | Notes |
|---|---|---|---|
| **AWS owned** | AWS (invisible to you) | AWS | Default for some services (for example DynamoDB), no control or audit |
| **AWS managed** (`aws/s3`, `aws/lambda`...) | AWS in your account | Automatic, **yearly** | You cannot edit the key policy |
| **Customer managed (CMK)** | You | **Optional** automatic rotation (default every 365 days, configurable period) or manual | Full control: key policy, grants, disable/delete |

* **Symmetric** keys (AES-256-GCM) never leave KMS; **asymmetric** keys (RSA, ECC) support sign/verify or encrypt/decrypt with a public key you can export.
* **Key policy** is the primary access control (required). IAM policies work **only if the key policy allows IAM to control access** (the default policy delegates to the account root). **Grants** give temporary, programmatic delegated access (used by services like EBS and RDS).
* **Encryption context:** optional key-value pairs authenticated with the ciphertext (AAD). It must match on decrypt, appears in CloudTrail, and can be used in policy conditions.
* **Multi-Region keys** let you encrypt in one Region and decrypt in another with the same key material.
* **Deletion:** mandatory waiting period of **7 to 30 days** (disable first if unsure).
* **Cross-account:** key policy must allow the other account **and** that account's IAM policies must grant the use.
* **`kms:ViaService`** condition limits a key to use through a specific service (for example only via S3).

```bash
aws kms create-key --description "app data key"
aws kms generate-data-key --key-id alias/app-key --key-spec AES_256      # returns Plaintext + CiphertextBlob
aws kms decrypt --ciphertext-blob fileb://encrypted-data-key.bin         # returns Plaintext data key
aws kms enable-key-rotation --key-id alias/app-key
```

## 3. Certificates and Keys for Development (Skills 2.2.2 and 2.2.5)

* **AWS Certificate Manager (ACM):** provisions **public TLS certificates for free** for use with integrated services (**ALB/NLB, CloudFront, API Gateway, Elastic Beanstalk**), with **automatic renewal** when using DNS validation. **Public ACM certificates cannot be installed on arbitrary servers (not exportable).** Validation: **DNS validation** (CNAME record, preferred, enables auto-renew) or email validation. **CloudFront and edge-optimized API custom domains need the certificate in us-east-1.**
* **AWS Private CA:** create a private certificate authority for **internal** endpoints, mutual TLS, IoT, or services in your VPC; private certificates can be exported and deployed.
* **Generating certificates and SSH keys locally:**

```bash
openssl req -x509 -newkey rsa:2048 -nodes -keyout dev.key -out dev.crt -days 30 -subj "/CN=localhost"
ssh-keygen -t ed25519 -f ~/.ssh/dev-key -C "dev@example.com"
aws ec2 create-key-pair --key-name dev-key --query KeyMaterial --output text > dev-key.pem && chmod 400 dev-key.pem
```

Private keys (`.pem`) are shown **only once** by EC2 key pair creation. Protect them; never commit them. For temporary shell access consider **EC2 Instance Connect** or **Systems Manager Session Manager** (no inbound SSH or keys to manage).

## 4. Secrets Management (Skill 2.2.7)

| Feature | **AWS Secrets Manager** | **SSM Parameter Store** |
|---|---|---|
| Primary purpose | Secrets with **automatic rotation** | Configuration values and simple secrets |
| Rotation | **Built-in** (Lambda-based; native templates for RDS, Aurora, Redshift, DocumentDB) | None built in |
| Encryption | Always KMS | `SecureString` with KMS (optional; standard strings are plaintext) |
| Cost | Per secret per month plus API calls | **Standard parameters free** (up to 10,000); Advanced parameters cost |
| Size | Up to 64 KB | 4 KB standard, 8 KB advanced |
| Versioning | Staging labels `AWSCURRENT`, `AWSPREVIOUS`, `AWSPENDING` | Parameter versions and labels |
| Cross-Region | Secret replication | Manual |
| Policies | Resource policy | Advanced tier supports expiration and notification policies |

**Retrieval patterns**

* SDK: `secretsmanager.get_secret_value(SecretId=...)` or `ssm.get_parameter(Name=..., WithDecryption=True)`.
* **Cache** results (Lambda: the **AWS Parameters and Secrets Lambda Extension**, or client-side caching libraries) to cut latency, cost, and throttling. Fetch **outside the handler** to reuse across invocations.
* **ECS task definitions** can inject secrets from Secrets Manager or Parameter Store as environment variables at start.
* **CloudFormation dynamic references** pull secrets at deploy time without exposing them in templates:

```yaml
MasterUserPassword: '{{resolve:secretsmanager:prod/db/creds:SecretString:password}}'
```

**Never** put secrets in source code, container images, plaintext environment variables, or CloudFormation parameters without `NoEcho` plus a dynamic reference. When a secret is rotated, applications must **re-fetch** (or rely on `AWSCURRENT`); long-cached values can break after rotation.

## 5. Identifying, Masking, and Limiting Access to Sensitive Data (Skill 2.2.6)

| Need | AWS Capability |
|---|---|
| Discover PII in **S3** at scale | **Amazon Macie** (managed data discovery and classification) |
| Detect and redact PII in **text** from your code | **Amazon Comprehend** PII detection (`DetectPiiEntities`, `ContainsPiiEntities`) |
| Mask sensitive values in **logs** | **CloudWatch Logs data protection policies** (detect and mask by managed identifiers such as credit card or SSN) |
| Filter PII in **generative AI** inputs and outputs | **Bedrock Guardrails** sensitive information filters (Module 10) |
| Limit who can read **specific fields or items** | IAM conditions (`dynamodb:Attributes`, `LeadingKeys`), column-level controls, separate KMS keys per sensitivity tier |
| Protect specific fields end to end | **CloudFront field-level encryption**, application-level encryption |
| Reduce exposure | **Tokenization** or hashing, collect less, short retention, avoid logging payloads |

The exam list is non-exhaustive: the pattern is to **use a managed detection or masking feature rather than writing custom regex-only code**, restrict access by least privilege, and keep PII/PHI out of logs, URLs, and error messages.

## 6. Common Exam Traps and Scenario Distractors

* "Encrypt data larger than 4 KB with KMS" → **envelope encryption** (`GenerateDataKey`).
* "Need to audit each use of the encryption key" → **SSE-KMS** (CloudTrail records KMS calls), not SSE-S3.
* "S3 with SSE-KMS gets `ThrottlingException` from KMS at high volume" → enable **S3 Bucket Keys**, request a quota increase.
* "Application can read the S3 object but gets AccessDenied" → missing **`kms:Decrypt`** on the key (or key policy).
* "Rotate database credentials automatically" → **Secrets Manager** (rotation Lambda).
* "Cheapest way to store non-rotating config and a few secrets" → **Parameter Store**.
* "Install a free ACM public certificate on an EC2 web server" → **not possible**; use ALB/CloudFront or a Private CA certificate.
* "Customer must hold the key and provide it per request" → **SSE-C** (or client-side encryption).
* "Compliance requires immediate key invalidation" → **disable the key** (deletion has a 7 to 30 day wait).

## Self-Assessment & Exam Traps Checklist

- [ ] An app encrypts 2 GB backups. What is the correct way to use KMS?
<details>
<summary>Explanation</summary>

Call `GenerateDataKey`, encrypt locally with the plaintext data key, store the encrypted data key with the data, and discard the plaintext key. Decrypt the data key with KMS later. The AWS Encryption SDK automates this.

</details>
- [ ] A Lambda function reading SSE-KMS objects from S3 fails with AccessDenied although its role allows `s3:GetObject`. What is missing?
<details>
<summary>Explanation</summary>

Permission to use the KMS key (`kms:Decrypt`) in both the role's policy and the key policy (or a key policy that delegates to IAM).

</details>
- [ ] Database passwords must rotate every 30 days with no application downtime. Which service and feature?
<details>
<summary>Explanation</summary>

**AWS Secrets Manager** automatic rotation using the managed rotation template for the database engine. The app fetches `AWSCURRENT` (cache with a short TTL).

</details>
- [ ] Credit card numbers appear in application logs. What is the best managed control?
<details>
<summary>Explanation</summary>

A **CloudWatch Logs data protection policy** to detect and mask the sensitive data, plus stop logging the raw values in code.

</details>
- [ ] Which certificate option provides a free, auto-renewing TLS certificate for a CloudFront distribution?
<details>
<summary>Explanation</summary>

A **public ACM certificate requested in us-east-1** with DNS validation, attached to the distribution.

</details>
