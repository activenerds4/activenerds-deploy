## Question
What is the fundamental operational difference between absolute positional encodings (e.g., sinusoidal) and relative positional encodings like Rotary Position Embedding (RoPE), and why does RoPE extrapolate better to longer context lengths?


## Quick Answer
**Absolute positional encoding** adds a fixed vector representing "position 5" (or similar) directly to each token's embedding, while **RoPE** instead rotates the query and key vectors by an angle proportional to position, so the attention dot product itself ends up encoding the *relative* distance between two tokens.

## Detailed Answer
Sinusoidal absolute encodings, as used in the original Transformer, compute a fixed sine/cosine vector for each position index and add it elementwise to the token embedding before the first attention layer. The model has to learn, indirectly, how to interpret the difference between two positional vectors as "distance" — it's never told this explicitly, it's baked into raw embeddings that get mixed with content before any attention math happens.

**RoPE (Rotary Position Embedding)** takes a different approach: instead of adding a positional signal to the embedding, it multiplies each query and key vector by a rotation matrix whose angle depends on that token's position. The key mathematical property is that when you take the dot product of a rotated query at position $m$ and a rotated key at position $n$, the result depends only on $m - n$ — the **relative offset** — not on the absolute positions themselves. Attention scores become a direct function of relative distance by construction, rather than something the model has to infer from summed absolute vectors.

This is why RoPE **extrapolates better to longer context lengths** than absolute encodings: a model trained on sequences up to length 4096 with absolute encodings has simply never seen a "position 5000" vector — it's out of distribution and produces garbage. A RoPE-based model, however, has learned to interpret relative offsets, and a relative offset of, say, 200 tokens behaves consistently whether it occurs early or late in a much longer sequence, so performance degrades far more gracefully beyond the training length (though it still isn't perfect without additional scaling tricks like NTK-aware interpolation).

<Callout variant="tip" title="Key Takeaways">
RoPE encodes position as a relationship between tokens rather than a fixed label on each one, which is exactly the property that lets it generalize past the lengths it was trained on.
</Callout>
